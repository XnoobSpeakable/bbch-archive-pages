I arrived at the following set of rules. They ended up being quite similar to the ones found by Polygon, although I did my analysis independently. Let the notation "`a ... b [m] c ... d`" mean `0^inf 1^a 0 ... 0 1^b 0 1^m 0B> 0 1^c 0 ... 0 1^d 0^inf`. (So basically a series of numbers in unary.) Also let "L" denote the `0^inf` on the left side. Then we have the following rules: ``` a. L 1 [0] c ... -> L [c+4] ... b. L 2 [0] c ... -> L 2 [c+2] ... c. L 3 [0] c ... -> ***HALT*** d. L 4 [0] c ... -> L [c+8] ... e. L 2k+5 [0] c ... -> L 2 [2k+1] c+4 ... f. ... a 2k+6 [0] c ... -> ... a+1 [2k+2] c+4 ... g. ... a [1] c ... -> ... [a+c+3] ... h. ... a [4k+2] b ... -> ... a+k+2 [b+3k+1] ... i. There are either one or two big numbers in the list. When there are two big numbers, the left big number might get smaller and smaller and if it reaches 3, then the machine halts by rule `c` or `i`. This could happen if the machine keeps going between configurations `B [B] 3s`, `1 [B0] B 3s`, `B [0] B 3s`. The red arrows in the diagram make the left big number significantly smaller and the green arrows make it larger. However, the machine most likely will reset back to a configuration with only one big number. As the machine continues, the numbers grow rapidly, thanks to the `j` rule basically multiplying a number by 3, such that it becomes increasingly unlikely for the machine to halt -- the TM would need to have a long sequence of the correct transitions and avoid resetting.
